## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ npm install
```

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

## Run tests

```bash
# unit tests
$ npm run test

# e2e tests
$ npm run test:e2e

# test coverage
$ npm run test:cov
```

## API profiling and load dashboard

Every HTTP API is measured automatically. Metrics include request count, error
rate, P50/P95/P99 latency, latency histograms, concurrent requests, CPU, memory,
and Node.js event-loop lag. Prisma queries include timing percentiles and slow
query detection. API and database measurements are grouped by tenant/domain.
Dynamic path parameters are grouped by their Nest route template, so
`/leads/1` and `/leads/2` appear as one API.

Start the application normally:

```bash
npm run start:dev
```

Generate some API traffic and open `http://localhost:<PORT>/profiling`. The live
dashboard and latency heatmap run inside this NestJS application; Docker and
external monitoring services are not required. Raw Prometheus-compatible
metrics remain available from `GET /metrics` for optional production scraping.
Protect both monitoring endpoints with your network/firewall in production.

The slow-query threshold defaults to 500 ms. Override it in `.env` when needed:

```env
PROFILING_SLOW_QUERY_MS=500
```

The profiler stores bounded in-memory samples (up to 2,048 per API/query and the
latest 100 slow queries), so metrics reset whenever the Node.js process restarts.

### API access and error logs

Requests are recorded centrally without changing controller return values,
response bodies, or status codes. Successful 2xx requests are written only to
`logs/access-YYYY-MM-DD.ndjson`. Redirects, 4xx/5xx responses, and other
non-success statuses are written only to `logs/error-YYYY-MM-DD.ndjson`. Each
line contains the endpoint, method, tenant/domain, final HTTP status, reason,
duration, and status classification. Files are removed automatically after
three days by the hourly log cleanup job.
If legacy code returns HTTP 200 but its response body contains a numeric
`statusCode` of 400 or higher, that logical failure is also recorded using the
body's failure code; the outgoing response is still left unchanged.

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
